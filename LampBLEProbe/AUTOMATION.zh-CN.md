# 随身 iPhone 到家开灯、离家关灯

**用户已实测通过（2026-10-30）：使用连接家庭 Wi-Fi → 开灯、断开家庭 Wi-Fi → 关灯，完整链路已跑通。** 当前实际使用 Wi-Fi 触发，下方地理围栏步骤为可选方案，无需重复配置。Wi-Fi 断开时随身手机需要可用互联网（通常是蜂窝数据）才能发送离家请求。长期在线及断网/掉线恢复稳定性尚未单独验收。

架构：随身 iPhone 的位置自动化 → HTTPS 请求 → ntfy.sh → 家中旧 iPhone 的蓝牙灯 App → 灯具。

本轮先让旧手机 App 保持前台，专注验证完整功能。后台、锁屏和长期驻留另行验收。两台手机都要联网，旧手机保持在灯的蓝牙覆盖内。

## 一、旧手机接收

1. Xcode 向旧手机 Run 安装最新源码，保持原 Bundle ID 和签名 Team，不删除 App。已有灯和密钥沿用。
2. 开启“常驻中枢模式”，等待读回状态。
3. 开启“接收云端开关请求”，等待“云端已连接，等待到家或离家请求”。
4. 打开“配置随身 iPhone 的自动化”。使用页面内复制按钮或分享，将请求地址、开灯内容、关灯内容传给自己的随身手机。它们是远程控制凭证，勿公开；不需要复制灯具密钥。

配置由旧手机本地随机生成，保存在独立 Keychain 项目；无需注册 ntfy 账号或另装 ntfy App。ntfy 的免费公共服务以不可猜测主题地址作为访问凭据，这里再加独立消息口令校验，并非账号权限隔离，也非端到端加密。服务可看到消息内容、时间和网络地址。位置坐标与蓝牙凭证不上传。服务默认缓存消息约 12 小时，中枢只接受 2 分钟内的有效消息。

## 二、随身手机创建两个发送快捷指令

**推荐直接导入** `Shortcuts/回家开灯.shortcut` 和 `Shortcuts/离家关灯.shortcut`，均已签名。导入时按提示填写旧手机的请求地址和对应内容，即可省去以下手工搭建步骤；详见 [导入说明](Shortcuts/README.zh-CN.md)。位置自动化仍按第三部分在随身手机设置。

先建立“回家开灯请求”：

1. 新建快捷指令，添加“文本”操作，粘贴旧手机提供的“开灯内容”，不添加空格或换行。
2. 添加“获取 URL 内容”（实际名称可能为“获取 URL 的内容”）。在其 URL 栏粘贴请求地址。
3. 展开设置，方法选 **POST**。
4. 请求体选 **文件**，文件值指定为第 1 步“文本”的输出变量。不是选磁盘文件，也不要用 JSON 或表单编码。
5. 手动运行，完成首次网络权限授权。在旧手机看到“开灯已回读确认”，并确认实体灯亮。

复制该快捷指令，改名“离家关灯请求”，将“文本”改为“关灯内容”。手动运行，确认旧手机显示“关灯已回读确认”且实体灯灭。

先把随身手机切换至蜂窝数据测试，可确认请求确实经互联网传递。HTTP 返回成功只代表服务接收了消息，不代表灯具执行成功；以旧手机的结果和灯具实际亮灭为准。

## 三、添加位置触发

在**随身手机**配置，不是在家中旧手机配置：

1. 打开“回家开灯请求”的编辑页面，为它添加“到达”家中的位置触发。
2. 打开“离家关灯请求”的编辑页面，为它添加“离开”同一位置的触发。
3. 将触发设置为无需确认/自动运行；如页面显示“立即运行”，选该项。
4. 在快捷指令的信息 → 隐私中启用允许锁定时运行（实际中文名称以页面为准）。
5. 按系统提示允许快捷指令使用定位。家庭地址在手机上选择，不需要发到聊天或服务端。

iOS 27 的自动化入口可能直接位于快捷指令编辑器。参考 [Apple 当前自动化指南](https://support.apple.com/en-euro/guide/shortcuts/apdfbdbd7123/10.0/ios/27)。如果你的页面不同，按实际界面继续，不套用旧版固定点击路径。

到达和离开按地理围栏判断，不精确到跨门的一瞬间：可能提前开灯、离开一段距离后关灯。默认全天生效，不附加夜间条件。

## 四、实际验收

1. 旧手机保持 App 前台，中枢和云端接收均已开启，灯具保持供电。
2. 带随身手机离开设置的围栏，保持手机锁定，不点运行，确认灯自动关闭。
3. 再回到围栏，保持手机锁定，不点运行，确认灯自动开启。
4. 分别记录旧手机的接收/回读结果和实体灯状态。只通过手动发送测试不能视为到家/离家自动化通过。

## 失败时的含义

- “云端连接中断”：中枢会退避重试；断网超过两分钟的旧请求不补执行。
- “请求已过期”：未执行。不会在很久以后补开/关灯。
- 中枢停止：请求丢弃；重新启动中枢后，需要新的自动化请求。
- 蓝牙正忙或正在重连：保留最新请求等待，最多到该请求原本的两分钟期限。更新的请求覆盖尚未开始执行的旧请求。
- 蓝牙执行失败或结果未知：不自动重放。设备可能已改变状态，不能显示假成功。
- 重复消息：持久化去重。停止、重启接收不会重复执行已经接收过的同一消息。

公共中转的网络可达性和额度影响可用性，系统位置触发也需真实验收。本地时钟应保持自动设置。没有承诺离线自动化、服务可用性或端到端送达保证。
